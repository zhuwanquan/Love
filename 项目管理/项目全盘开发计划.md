## 三、里程碑详解

### 里程碑 1：对话体原型 —— 第一个聊天框

**目标**：聊天界面在浏览器里跑起来，点击推进线性对话。**不需要选项，不需要变量。**

**对话体的独特要求**：
- 聊天气泡（左右对齐：机器人左、玩家右）
- 消息逐条出现（模拟真实聊天节奏）
- 打字指示器（"对方正在输入..."——对话体的关键沉浸元素）
- 对话历史自动滚动

**为什么聊天气泡的节奏很重要**：
对话体的沉浸感不来自立绘，而来自**消息的节奏感**——消息之间的停顿、句子长度、机器人的"正在输入..."暗示——这些比传统 VN 的文字推进更需要精细调校。

**剧本格式调整**（相比传统 VN 格式）：
```json
[
  { "role": "rc",  "text": "你好。我是 RC-Edu-7。", "delay": 800 },
  { "role": "rc",  "text": "请告诉我，你希望我怎么称呼你？", "delay": 1200 },
  { "role": "player", "text": "叫我小陈就好。" },
  { "role": "rc",  "text": "好的，小陈。", "delay": 600 },
  { "role": "rc",  "text": "今天过得怎么样？", "delay": 2000 }
]
```

**产出**：
- `index.html`（聊天界面 + 脚本引擎 ~150 行）
- `scripts/day-01.json`（节点日1前30-40条消息）

**检查点**：双击 index.html，从头到尾"聊完"节点日1，节奏感自然。

---

### 里程碑 2：选择分支 —— 快捷回复

**目标**：玩家能在 2-3 个快捷回复中选择，不同选择走向不同对话。

**对话体下的选择形态**：
- 选项以**聊天气泡按钮**的形式出现在输入区上方（类似微信快捷回复/Telegram inline buttons）
- 点击后选项消失，选中的那条作为玩家的消息出现在聊天记录中
- 未选中的选项不显示在聊天历史中（保持对话的"自然感"）

**关键设计**：选项文本必须是"人话"——读起来像真实的人会打出的回复，而不是"选项A：表示同意"式的元游戏语言。

**检查点**：节点日1含 2-3 个选择点，不同选择看到不同对话。

---

### 里程碑 3：变量系统 —— 选择有后果

**目标**：关系值（trust/closeness）和 flag 累积，影响后续对话。

与传统 VN 的变量系统完全相同——只是存储的是聊天行为而非 VN 选项。参考 [[单人开发顺序指南#里程碑3]] 的实现。

**对话体下特有的变量追踪**：
- 不只是"选了哪个选项"，还可以追踪"有没有主动发起深夜对话"、"有没有问过私人问题"、"沉默/输入框空白的时间长度"
- 这些行为变量比选项变量更有对话体的特色

**检查点**：不同累积路径触发不同的反馈（如 trust≥2 时道晚安方式不同）。

---

### 里程碑 4：存档闭环

**目标**：存档/读档/主菜单完整可用。

与 [[单人开发顺序指南#里程碑4]] 完全一致。对话体新增一个字段：**聊天历史**（消息列表的完整存档，用于回看）。

**回看功能**（Backlog）：对话体的"历史回看"比传统 VN 更重要——它模拟了翻聊天记录的真实行为。

**检查点**：完整的"打开→新游戏→玩→存档→退出→读档→继续"闭环。

---

### 里程碑 5：视觉层 —— 对话体 UI 润色

**目标**：聊天界面从"功能可用"升级到"有沉浸感"。

**对话体独特的视觉要素**（相比传统 VN 的立绘+背景）：

| 要素 | 说明 | 优先级 |
|------|------|--------|
| 聊天气泡样式 | 圆角+阴影+左右颜色区分（RC浅蓝/灰 vs 玩家绿色） | 必须 |
| 叙事卡片 | 非对话文本（环境描写、过渡叙事）以特殊卡片形式插入聊天流 | 必须 |
| "正在输入..."动画 | 机器人打字时显示跳动的省略号或波纹 | 必须 |
| 日期/时间分隔线 | "节点日 1 · 深夜 23:12" 作为聊天流中的分隔标记 | 必须 |
| 头像 | RC-Edu-7 的小圆头像（简单几何图形占位即可） | 应该 |
| 过渡卡片 | 节点日之间的叙事过渡以全屏/半屏卡片呈现 | 应该 |
| 玩家头像 | 可选——白色剪影或可自定义 | 可选 |

**叙事卡片是对话体中最重要的视觉创新**：

```
聊天流中：
┌──────────────────────────────────┐
│  [RC] 今天的学习到此为止。        │  ← 普通聊天气泡
│  [RC] 晚安，小陈。               │
│                                  │
│  ┌────────────────────────────┐  │
│  │ 🌙                          │  │
│  │ 窗外有车经过。              │  │  ← 叙事卡片
│  │ 光柱扫过天花板，又消失了。   │  │     (环境/内心/过渡)
│  │ 手机屏幕的光映在你脸上。    │  │
│  └────────────────────────────┘  │
│                                  │
│  ─── 节点日 1 · 完 ───           │  ← 分隔线
└──────────────────────────────────┘
```

**节奏规则**：玩家发消息 → 机器人回复（可多条） → 叙事卡片 → 玩家再发消息。叙事卡片的插入时机决定了节奏的"呼吸感"。

---

### 里程碑 6：全部内容

**目标**：8 个节点日 + 4 个结局全部写完并跑通。

与 [[单人开发顺序指南#里程碑6]] 一致。额外强调：

- **叙事卡片的文本风格**：必须用中文写作中最克制、最不煽情的描述方式——日本治愈系的"留白"和"间"——而不是韩国式的直白催泪
- **每天只写一个节点日，写完就跑一遍**——这是维持写作动力的关键节奏
- **开发者面板**（按 ` 呼出）在这个阶段是救命工具

---

### 里程碑 7：AI 模式对接

**目标**：主页双入口，AI 模式可用。

**相比原指南的调整**：原指南把 AI 模式放在最后（里程碑9），但考虑到：
- System Prompt v1 已经在 MVP 原型中验证过可用（75821e1 commit）
- AI 模式是核心差异化卖点
- 传统模式内容生产（里程碑6）期间可以并行测试 AI 管线

**建议将 AI 模式从"最后做"调整为"里程碑6完成后立即做"**——此时传统模式已有完整可玩的版本，AI 模式作为一个"平行入口"加入。

**AI 模式的核心工作**：
1. 主页面双入口 UI（传统模式 / AI 模式）
2. API 密钥配置页
3. `LLMDriver` 抽象层（DeepSeek 实现 + MCP 协议预留）
4. AI 对话管线：System Prompt + 记忆 → 调用 API → 返回
5. 叙事卡片插入逻辑（AI 模式下叙事卡片仍为预设文本，在特定节点自动触发）
6. 结局判定（与传统模式共享变量系统判定条件）

**AI 模式下的关键设计决策**：
- **叙事卡片保持预设**——AI 不生成叙事卡片，只生成对话。这保证了核心叙事质量不被 LLM 稀释
- **AI 模式也走节点日结构**——不是无结构闲聊，是在固定骨架上的自由对话
- **AI 模式下变量追踪简化**——没有快捷回复选项，改为追踪自然对话中的行为标记

---

### 里程碑 8：打磨与发布

**目标**：可分发、可下载、可完整游玩的 v1.0。

**新增测试 checklist（对话体特有）**：
- [ ] 聊天节奏在不同阅读速度下是否自然
- [ ] 叙事卡片的插入时机是否打断了对话流
- [ ] "正在输入..."延迟是否合理（太快=假，太慢=不耐烦）
- [ ] 对话历史回看是否完整
- [ ] 在手机屏幕尺寸下的聊天气泡可读性

**发布目标**：Web 版优先（GitHub Pages/Netlify），桌面版（Electron）作为选项。

---

### 里程碑 9：运营准备

**目标**：游戏上线后的用户获取和反馈基础设施。

- 应用商店页面（如选择上架）
- 社交媒体账号（小红书/微博——匹配核心受众 18-28 女性）
- 反馈收集渠道（问卷/社区）
- 内容更新计划（是否有后续 DLC/新结局/节日特殊对话）

## 四、MVP 定义（最小可行原型）

基于 [[实现路线图]] 的 MVP 概念（已有原型 commit 75821e1），更新 MVP 定义为：

```
MVP = 里程碑 1 + 节点日1的完整剧本 + System Prompt v1
    = 一个聊天界面，在浏览器里打开
    = RC-Edu-7 用固定人设回应
    = 玩家从头到尾"聊完"第一次激活的场景
    = 15-20轮对话后自然结束

验证假设：
  "在没有立绘、没有BGM、只有一个聊天框的情况下，
   一个没有主观能动性的AI能否让玩家觉得……
   有什么东西在那里。"
```

**MVP 完成状态**：75821e1 commit 已验证 System Prompt 可用。下一步是将其嵌入聊天气泡界面（里程碑1的核心工作）。

## 五、风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| **叙事卡片写作难度** | 高 | 先写 3-4 张实验性卡片测试效果。风格参考：村上春树短篇的环境描写密度——一句话一个意象，不超过三句话。 |
| **AI 模式下人设一致性** | 高 | System Prompt 中内化约束，节点日叙事卡片作为"锚点"固定上下文。每次会话开始时注入角色状态卡。 |
| **对话体节奏调校** | 中 | 频繁真人试读——每写完一个节点日就找一个人点击阅读，观察哪里不耐烦、哪里太快。 |
| **DeepSeek API 可用性** | 中 | MCP 协议预留替换接口。AI 模式设计为"LLM 无关"——换模型只需改 driver。 |
| **单人内容生产瓶颈** | 高 | 严格遵循"写完一节→跑通→调整"的节奏，不在写作阶段追求完美。8 个节点日，每个节点日目标 3-5 天，总写作周期 1-2 个月可控。 |
| **受众的内容调性** | 高 | RC-Edu-7 的语调必须做到"平等的温柔"——不是居高临下的建议，不是圣母式的牺牲，不是追问式关心。每句台词自问：**"这句话是在关心他，还是在要求他回应我的关心？"** 男性受众的核心需求是"被看见但不被要求解释"。详见 [[年轻男性消费习惯深度分析#RC-Edu-7的语调]] |
