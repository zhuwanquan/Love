## 一、技术选型

### 1.1 跨平台框架

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|--------|
| **React Native** | 生态成熟、热更新方便、与 Web 技术栈共享 | 复杂动画性能一般 | ⭐⭐⭐⭐ |
| **Flutter** | 性能好、UI 一致性强 | Dart 生态较小、热更新受限 | ⭐⭐⭐ |
| **Unity** | 游戏引擎功能完整、动画/特效强 | 重、UI 系统不适合聊天界面 | ⭐⭐ |
| **PWA（Web 封装）** | 开发最快、热更新零成本 | 体验不如原生、iOS 限制多 | ⭐⭐⭐ |

**建议：React Native 或 PWA + 原生壳**。这个游戏的核心是聊天界面 + 叙事文本，不需要游戏引擎的复杂功能。React Native 的聊天 UI 组件成熟，且方便后续集成微信登录/支付等国内 SDK。

### 1.2 LLM 方案

| 方案 | 成本（每用户完整游玩） | 中文质量 | 延迟 |
|------|----------------------|---------|------|
| Claude API（海外） | ~$0.5-1.5 | ⭐⭐⭐⭐⭐ | 1-2s |
| DeepSeek API（国内） | ~¥0.5-1 | ⭐⭐⭐⭐ | 0.5-1.5s |
| 通义千问 API | ~¥1-2 | ⭐⭐⭐⭐ | 0.5-1s |
| 本地模型（设备端） | 0（一次性） | ⭐⭐ | 取决于设备 |
| 自部署开源模型 | 服务器成本 | ⭐⭐⭐ | 可控 |

**建议架构**：
```
手机客户端 → 你的后端服务器 → LLM API
                ↓
           System Prompt 管理
           记忆系统
           内容安全过滤
           用量统计与限流
```

**绝不能**让手机客户端直接调用 LLM API——API Key 会暴露，且无法控制用量。

**关键考量**：如果在国内发行，需要考虑：
- 海外 API（Claude/GPT）的网络可达性和延迟
- 国内 LLM（DeepSeek/通义千问）是否能达到同样的人格一致性
- **建议 MVP 阶段用 Claude 验证人设，正式版接入 DeepSeek 或通义千问**

### 1.3 后端基础设施

| 组件 | 用途 | 建议方案 |
|------|------|---------|
| API 服务器 | 接收客户端请求，调用 LLM，返回响应 | Node.js/Python + Nginx |
| 记忆数据库 | 存储玩家对话历史和提取的关键记忆 | PostgreSQL（结构化数据）+ 向量数据库（可选） |
| 用户系统 | 注册/登录/存档 | 手机号 + 验证码（国内标配） |
| 内容安全 | 过滤违规输入和输出 | 第三方内容安全 API + 敏感词库 |
| 静态资源 | 场景图、UI 素材、音效 | CDN / OSS |
| 监控与日志 | 排查问题、用量统计 | 阿里云/腾讯云监控 |

## 二、游戏系统设计

### 2.1 需要从零实现的系统

| 系统 | 说明 | 复杂度 |
|------|------|--------|
| **对话引擎** | 管理 System Prompt + 记忆注入 + 上下文窗口 | ⭐⭐⭐ |
| **记忆系统** | 每节点日后提取关键事件 → 存储 → 下次注入 | ⭐⭐⭐⭐ |
| **存档系统** | 保存玩家进度（当前节点日、历史对话摘要、关系值） | ⭐⭐ |
| **关系值追踪** | 根据对话内容计算互动深度/情感表达/回避模式 | ⭐⭐⭐ |
| **结局判定** | Day 8 根据累积数据判定 A/B/C/D | ⭐⭐ |
| **场景管理器** | 控制节点日切换、过渡文本展示、对话轮数限制 | ⭐⭐ |
| **资源管理** | 每个玩家的 Token 预算控制 | ⭐⭐ |

### 2.2 记忆系统详细设计

这是整个游戏最难的部分。8 个节点日跨 18 周，需要机器人在 Day 8"记得"Day 1 的内容。

```
每次节点日对话结束后：
  对话全文 → LLM 提取关键记忆（摘要） → 存入数据库

下一个节点日开始前：
  从数据库取出本玩家的所有记忆 → 按重要性排序 → 取 Top-N 条注入 System Prompt

注入格式：
"[以下是你与该使用者的历史关键记忆]
- Day 1（第1周）：使用者为大一新生，专业为计算机科学。首次对话中表现出试探性语气。
- Day 3（第3周）：使用者在深夜对话中提到了对专业选择的不确定感。
- Day 4（第6周）：使用者线性代数测验成绩68分。在失败后出现了自我否定的语言模式。
- Day 6（第13周）：使用者在情绪崩溃中透露了与父亲的疏远关系。'
```

### 2.3 关系值追踪

从对话内容中提取量化指标，用于结局判定：

| 指标 | 计算方式 |
|------|---------|
| **互动深度** | 总对话轮数 × 平均每轮字数 |
| **非学习占比** | 非学术对话轮数 / 总轮数 |
| **情感暴露度** | 包含情绪关键词的轮数 / 总轮数 |
| **回避接受度** | 玩家对隐形回避的响应为"接受型"的次数 |

## 四、运营准备

### 4.1 成本模型

**单用户成本估算**（以 Claude Sonnet 为例，8 个节点日完整游玩）：

| 项目 | 成本 |
|------|------|
| LLM API 调用 | $0.5-1.5（约 ¥3.5-10） |
| 服务器与带宽 | ¥0.1-0.3/用户 |
| 内容安全审核 API | ¥0.05-0.1/用户 |
| **合计** | **约 ¥4-11/用户** |

如果日活 1000 人，每人完整游玩一次，月 LLM 成本约 ¥4000-11000。如果使用 DeepSeek 等国内模型，成本可能降到 1/3-1/5。

**定价策略建议**：
- 免费下载 + 前 3 个节点日免费 → 后续付费解锁（¥6-12）
- 或：一次性买断（¥12-18），包含完整 8 个节点日
- 注意：国内 App Store 对"内购"有版号要求，买断制可能更简单

### 4.2 国内发行的特殊要求

| 要求 | 说明 | 时间周期 |
|------|------|---------|
| **版号（ISBN）** | 国内 App Store 和安卓渠道上线必需 | 6-18 个月（极不确定） |
| **ICP 备案** | 后端服务器必须备案 | 2-4 周 |
| **内容安全** | 用户生成内容（UGC）的过滤——玩家自由输入文本，必须接入内容安全审核 | 技术集成 |
| **隐私政策** | 玩家对话数据属于高度敏感信息，需要明确的隐私政策 | 法务审核 |
| **未成年人保护** | 防沉迷系统、未成年人消费限制 | 技术集成 |

**关于版号的最重要提醒**：如果你的游戏包含了"聊天"功能并且内容由 AI 生成，它可能被归类为"具有内容发布功能的网络游戏"或"AI 内容生成服务"，这两者在当前的国内监管框架下都是高度敏感的分类。**建议先以 TestFlight/海外发行/Web 应用的方式验证产品和商业模式，再考虑国内应用商店上架。**

### 4.3 替代发行策略

如果跳过国内应用商店：
- **海外 App Store / Google Play**：无需版号，但需要英文适配
- **Web 应用（PWA）**：完全绕过应用商店，通过网址直接访问
- **微信小程序**：审核比独立 App 宽松，但功能受限
- **Steam**：PC 端发行，作为"互动小说"品类，无需版号
