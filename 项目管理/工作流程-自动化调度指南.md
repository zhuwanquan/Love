# 一年·房间 — 固定工作流程自动化调度指南

> 本文档精炼项目中所有可重复的固定工作流程，供 Claude Code 自动识别调度。
> 每个流程标注触发条件、输入、步骤、输出、预计耗时。

---

## 流程总览

```
剧本修改 → [P1] 快速测试 → [P2] 机械验证 → [P3] 三维并行审查 → [P4] 情感结构 → [P5] 结局走查 → [P6] 综合评分
引擎修改 → [P1] 快速测试
发布前   → [P1]→[P2]→[P3]→[P4]→[P5]→[P6] 全链
```

## P0 · 构建与部署

### P0.1 Web 部署（自动）

**触发**：推送到 `game` 分支
**流程**：`git push origin game` → GitHub Actions `deploy.yml` → Pages 自动部署
**验证**：`gh run list --branch game --limit 1` 确认 `completed success`
**在线地址**：https://zhuwanquan.github.io/Love/

### P0.2 APK 构建（自动）

**触发**：推送到 `v2-romance` 分支（`game/www/**` 或 `game/android/**` 变更）
**流程**：GitHub Actions `build-apk.yml` → JDK 17 + Gradle → 上传 debug APK artifact
**验证**：`gh run list --branch v2-romance --limit 1` 确认 `completed success`
**常见失败**：阿里云 Maven 镜像 502 → 已修复（`google()`/`mavenCentral()` 优先）
**产物保留**：30 天

## P1 · 快速测试 `game-test-runner`

**触发**：每次修改 `game/www/data/day*.js` 或 `game/www/js/engine.js` 后
**输入**：全部 8 个 day JS 文件 + engine.js
**耗时**：~30 秒

**步骤**：
1. 语法检查 — `new Function(code)` 验证 9 个 JS 文件
2. 场景统计 — 每 Day 的 scene/rc/player/narration/choices/variable/goto 计数
3. 冒烟测试 — `node game/tests/smoke_test.js`（目标 16/16）
4. Goto 完整性 — 所有 goto/choices.goto/next 目标存在性
5. RC-7 统计 — 总条数/字数/平均/最长（检查 250 字限制）

**输出**：五项通过/失败报告
**调用**：`/game-test-runner`

## P2 · 机械验证 `script-validator`

**触发**：P1 通过后；剧本结构调整后
**输入**：全部 8 个 day JS 文件
**耗时**：~2 分钟

**步骤**：
1. Goto 目标存在性 — 所有跳转目标是否在 scenes 中
2. 场景可达性 — 从 `day1_opening` BFS 遍历，找出孤立场景
3. 跨日引用一致性 — RC-7 回溯引用是否在早期 Day 中存在
4. 变量操作有效性 — 所有变量操作是否在 meta.variables 中初始化，格式是否正确
5. 结构完整性 — 元数据块、Day 8 结尾块、空场景检查

**输出**：断裂引用数 / 可达场景比例 / 跨日断裂数 / 变量有效性 / 结构统计
**调用**：`/script-validator`

## P3 · 三维并行审查

P3 三步可并行运行，覆盖不同维度。

### P3a · 旁白审查 `narration-auditor`

**触发**：P2 通过后；旁白文本修改后
**输入**：全部 `type: 'narration'` 行
**耗时**：~2 分钟

**四问审查**：
1. 是否在描述环境？（是 → 应删除或改视觉过渡）
2. 是否在告知玩家感受？（是 → 必须删除）
3. 删除后对话是否仍成立？（是 → 可删除）
4. 是否有深夜出租屋质感？（否 → 太通用）

**专项检测**：环境描写密度 / 重复日常（脱鞋/躺下/外卖）≥3 次 / 情感操控句式 / 应改 day_transition 的文本

### P3b · RC-7 声音检查 `rc7-voice-check`

**触发**：P2 通过后；RC 对话修改后
**输入**：全部 `type: 'rc'` 行
**耗时**：~2 分钟

**五问框架**：每行打分（≥80% 行得 4/5 以上为合格）
1. 是否可追溯到五项人格原则之一？
2. 是否含有非法情感词语？
3. 是陈述事实还是表达自身？
4. 是否可以更短？
5. 是否为该角色独有？

**BLRI 抽查**：10 行 × 4 维度 1-6 分
**红旗词汇**：情感表达词（必须删除）/ 需审查词（「对不起」「可能」）/ 已允许词（数据化包装）
**独特性**：句号美学 / 精确性 / 数据语言 / 250 字限制 / 3 秒延迟

### P3c · 用户画像对齐 `persona-alignment`

**触发**：P2 通过后；玩家台词修改后
**输入**：全部文件 + `最终内容/核心设定/用户画像-原子化社会青年.md`
**耗时**：~2 分钟

**检查项**：
1. 玩家词汇量 — 不应出现「沮丧」「孤独」「想你」等词
2. 家庭假设 — 搜索家庭相关词汇，确保有无家庭的替代路径
3. 节日框架 — 节日应为孤独的对比板，非温馨背景
4. 情感真实性 — 逐 Day 与预期用户状态对比
5. 「定义权在你」密度 — 目标 ≥3 次（Day 1/5/8）

**输出**：词汇违规数 / 家庭假设问题 / 逐 Day 情感匹配 / 定义权计数 / 对齐百分比

## P4 · 情感弧线分析 `emotional-arc-visualizer`

**触发**：P3 通过后；剧本结构调整后
**输入**：全部 8 个 day JS 文件
**耗时**：~3 分钟

**步骤**：
1. 情感强度计算 — 每行 0-10 分（typingDelay≥3s +2 / 锚点短语 +3）
2. 三弧线验证 — 弧1(Day1-3安全建立)→弧2(Day4-6脆弱被接住)→弧3(Day7-8准备离开)
3. 锚点分布 — 7 个核心锚点是否均匀分布
4. 节奏诊断 — 平坦段(连续≥15行≤2) / 过密段(连续≥5行≥6) / 突然跳跃(邻行Δ≥5) / 结尾拖沓

**输出**：每日情感强度图 / 三弧线通过/警告/严重 / 锚点分布 / 节奏问题列表

---

## P5 · 结局走查 `ending-path-walker`

**触发**：P4 通过后；Day 8 或变量修改后
**输入**：全部文件（重点关注 Day 8 endings 块 + 变量累积路径）
**耗时**：~3 分钟

**步骤**：
1. 条件分析 — 4 结局的条件覆盖/重叠/不可达检查
2. 变量累积 — 每变量理论最大/最小值 vs 结局条件阈值
3. 逐结局路径走查 — A(数据保留) B(始终如一) C(确认) D(数据持久化)
4. 兜底机制 — 全部锁定→解锁 D 的逻辑验证
5. 差异化评估 — 4 结局的情感落点/RC 回应/玩家收获是否足够不同

**输出**：条件表 / 变量范围 / 4 结局可达成性 / 兜底验证 / 差异化矩阵

---

## P6 · 综合评分 `script-evaluator`

**触发**：P5 通过后；发布前
**输入**：全部 8 个 day JS 文件
**耗时**：~5 分钟

**步骤**：
1. 六维度加权评分（满分 35）：故事骨架×1 + 角色塑造×1.5 + 分支设计×1 + 情感设计×2 + 节奏控制×1 + 世界观基调×0.5
2. 项目专项检查：机器人角色平衡 / 白板主角代入 / 日常真实性
3. 红灯（必须修）/ 黄灯（建议修）/ 绿灯（加分项）清单

**输出**：加权评分表 / 红黄绿灯 / 逐 Day 评价 / Top 3 改进建议

## 发布流程

```
P1→P2→P3→P4→P5→P6 全链通过
  → 开发者自测（全路径+存档+边界）
    → 亲友内测（5-8人 / 6题问卷 / 持续3-5天）
      → 封闭Beta（10-20人 / 移动端兼容性 / 持续1-2周）
        → 上架
```

**上架前检查清单**（7 项）：
- [ ] P6 评分 ≥ 21/35（及格）
- [ ] 游戏完整评价体系 H 维度 ≥ 15/50
- [ ] 全链 P1-P5 无红灯
- [ ] 4 结局全路径走通
- [ ] 存档/读档/删除 完整循环
- [ ] PWA 安装正常
- [ ] 隐私声明可访问

## 调度规则

| 变更类型 | 自动触发流程 |
|----------|-------------|
| 修改 `day*.js` 任一文件 | P1 |
| 修改 `engine.js` | P1 |
| 新增/删除/重命名场景 | P1 → P2 |
| 修改旁白文本 | P1 → P3a |
| 修改 RC 对话 | P1 → P3b |
| 修改玩家台词 | P1 → P3c |
| 调整 Day 顺序/结构 | P1 → P2 → P4 |
| 修改 Day 8 结局/变量条件 | P1 → P2 → P5 |
| 发布前 | P1 → P2 → P3a+P3b+P3c → P4 → P5 → P6 |
| 推送到 game 分支 | P0.1（自动） |
| 推送到 v2-romance 分支 | P0.2（自动） |
