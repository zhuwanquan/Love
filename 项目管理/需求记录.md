## 需求 #1：双模式展示系统

**日期**：2026-06-19
**状态**：🌳 已确定

### 概述

故事采用两种展示模式，面向不同深度的用户。主页面直接展示两个入口，用户无需任何隐藏操作即可看到两种模式的存在。

### 模式一：传统文字恋爱游戏（默认模式）

- 标准视觉小说/文字恋爱游戏的体验
- 固定的对话分支、预设的剧情走向
- 不需要任何外部 API 密钥即可游玩
- 面向所有玩家的、安全可控的体验

### 模式二：AI 模式（DeepSeek 驱动）

- **入口**：主页面直接显示，与传统模式并列
- **解锁条件**：用户持有 DeepSeek API 密钥，在应用内配置后即可进入
- 调用 DeepSeek API，针对玩家在表达游戏主旨和内涵时给出最佳回答
- 具体实现由项目作者后续自行完成

### 已确定的设计决策

| # | 问题 | 结论 |
|---|------|------|
| 1 | 两种模式是否共享故事骨架？ | **是**——两套模式共用同一套故事骨架、节点日结构、剧情触发条件。差异仅在对话生成层的实现方式（预设文本 vs LLM 实时生成） |
| 2 | AI 模式的核心差异是什么？ | 当玩家触及游戏主旨和内涵表达时，AI 模式通过 DeepSeek API 给出**最佳回答**，而非预设的有限分支回应。传统模式下这些时刻走固定分支文本 |
| 3 | 密钥验证方式？ | **页面级划分**——主页面直接显示两个入口按钮/卡片：「传统模式」和「AI 模式」。点击 AI 模式时要求配置 API 密钥。整个项目为单机设计，一切内容在用户设备上运行 |
| 4 | 为什么选 DeepSeek？ | **性价比最优**——目前 DeepSeek 价格最低、中文能力强。后期如出现更优模型，通过 **MCP 协议**进行替换。需求设计上需预留可替换的 LLM 调用模块 |

### 架构影响

双模式设计引出以下技术需求（详见 [[双模式架构与独立部署方案]]）：
- 全部单机运行，无服务端依赖
- LLM 调用模块可替换（MCP 协议预留）
- 主页面双入口 UI

## 需求 #2：交互形式确定——对话体治愈叙事

**日期**：2026-06-19
**状态**：🌳 已确定

### 概述

经过中日韩三国对比分析（详见 [[中国本土化形式分析]]），确定本项目的交互形式为**"对话体"（类微信聊天界面）**，而非传统视觉小说的全屏文本+立绘形式。

### 核心理由

- 类微信聊天界面是中国用户最熟悉的数字交互肌记忆
- 对话体天然适配碎片化使用（聊两句→关掉→继续聊）
- 对话体是唯一不需要预设主角身份的叙事形式（天然适配"白板主角"）
- 对话体对美术资源需求极低（头像+气泡颜色即可启动）
- AI 陪伴产品（星野/Glow/猫箱）已验证中国用户接受此类界面

### 关键澄清

> **删除的是传统VN的剧本格式（大段旁白+立绘+选项按钮），不是传统模式的叙事内容（8个节点日+关键事件+结局+机器人人设）。**
>
> 对话体下的传统模式 = 同样的叙事DNA，表达为"聊天记录"形态。
> 传统模式保证叙事完整性，AI模式在骨架上打开自由对话深度。

### 两种模式在对话体下的定位

| | 传统模式（预设脚本） | AI模式（DeepSeek） |
|---|---|---|
| **内容** | 脚本化的聊天消息+叙事卡片+快捷回复 | 同一叙事骨架，LLM实时生成回应 |
| **输入** | 2-3个快捷回复选项 + 关键节点自由输入 | 全程自由文本输入 |
| **保证** | 每个人都能体验完整的故事弧线 | 想聊得更深的玩家不被选项束缚 |
| **关系** | 地基——叙事完整性的底线 | 扩展——对话深度的天花板 |

### 三国公式总结

```
日本：长文本阅读 + 立绘 + 催泪叙事 → "在虚构中安全地哭泣"
韩国：即时通讯模拟 + 真实时间 + 轻触控 → "在虚拟中获得连接"
中国：对话体界面 + 叙事卡片 + 节点日结构 → "翻开聊天记录，发现自己被理解了"
```

## 需求 #3：多角色剧本探索 → 否决

**日期**：2026-06-20
**状态**：❌ 废弃

### 概述

探索玩家扮演不同职业身份、面对不同身份机器人的"多套剧本"方案。经过日韩产品对比分析（详见 [[多角色剧本可行性分析]]），**否决**。结论：单一剧本 + 单一核心关系（RC-Edu-7）。

### 核心理由

- 日本验证：galgame 多主角系统（Axanael）叫好不叫座，市场选择"一个主角走到底"
- 韩国验证：Storypick 多独立剧本模式稀释角色情感依恋，玩家爱的是"故事"不是"人"
- 中国验证：7000万国乙玩家核心行为是"单推"——排他性深度绑定一个角色
- RC-Edu-7 需要成为被"单推"的那个角色

### 保留的折中

在同一剧本内提供 2-3 个轻量开局身份标签（在工作/在找工作/还在读），不影响核心叙事骨架。

## 需求 #4：核心受众确定——18-30岁年轻男性

**日期**：2026-06-20
**状态**：🌳 已确定

### 概述

最初基于中国当前横截面数据（乙女游戏+AI陪伴）误判核心受众为18-28岁女性。用户指出经济下行期的日韩历史规律显示**男性是治愈内容最先爆发且体量最大的群体**。经验证，修正核心受众为18-30岁年轻男性。

### 关键证据链

- 日本：1999年"癒し系"概念起源于 GEORGIA 咖啡广告→目标疲惫男性上班族；galgame 巅峰 560亿日元/年，是乙女游戏的 10 倍以上
- 韩国：1997 IMF 危机后 PC방 爆炸→男性主导游戏消费；女性向互动小说晚了 15 年以上
- 中国：《完蛋！》90%+男性玩家，8000万销售额，验证男性情感消费需求

详见 [[治愈系受众画像分析]]、[[年轻男性消费习惯深度分析]]

## 需求 #5：剧本场景重设——「一年·房间」

**日期**：2026-06-20
**状态**：🌳 已确定

### 概述

废弃 v1 剧本（大学生+学期考试+毕业），采用新场景：**城市出租屋 + 传统节日骨架 + 深夜日常聊天**，时间跨度一年（夏末→夏至）。

### 核心理由

- v1 的大学生设定与核心受众（18-30岁男性，不全是学生）错位
- 学期节点日间隔稀疏（2-3周），浪费对话体的日常亲密感
- 传统节日（中秋/冬至/春节/清明/夏至）是每个中国年轻人秒懂的情感触发器
- 出租屋是18-30岁中国男性最大的共同生活经验

### 8个节点日

夏末初遇 → 中秋月圆 → 深秋糟糕的一天 → 冬至最长夜 → 春节回家？ → 初春崩裂 → 清明想起 → 夏至一年

详见 [[一年房间-剧本框架]]
