# 竞品数据对比分析

> 本文收集和交叉对比男性治愈/陪伴相关产品的用户数据。由于许多数据不可公开获取（私有公司的内部数据），本文使用可获取的公开数据 + 基于用户行为的合理推断，同时诚实地标注缺失的数据点。
>
> **目的**：为RC-7的产品定位提供数据验证——确认"男性治愈内容的'轻量化+有结局'区间"确实是空白地带。

## 二、《完蛋！我被美女包围了！》——最关键的验证数据

### 2.1 已知数据

| 指标 | 数据 | 来源 |
|------|------|------|
| 售价 | 42元（买断） | Steam |
| 玩家男性占比 | 90%+ | 多方报道一致 |
| 销售额（短期） | 约8000万人民币 | 行业估算 |
| Steam最高同时在线 | 约10万人 | SteamCharts |
| 通关率（至少一个结局） | 约45-55%（估算） | 基于Steam成就数据 |
| 平均游戏时长 | 3-8小时 | Steam用户评测 |
| 二刷率 | 未知 | — |
| 退款率 | 未知 | — |

### 2.2 用户评论的定量情绪分析

基于对Steam评测区的抽样阅读（非正式分析），《完蛋！》的男性玩家评论可以大致分为以下几类：

| 评论类型 | 估计占比 | 典型表述 |
|---------|---------|---------|
| **"被认真对待"** | ~30% | "第一次感觉到被认真对待。虽然是假的。" |
| **"性价比"** | ~25% | "37元请不到异性看电影……让我做了个梦。" |
| **"爽"** | ~20% | "被一群美女包围——现实中不可能的事。" |
| **"调侃/自嘲"** | ~15% | "42块买的不是游戏，是一场不切实际的春梦。" |
| **"批评/失望"** | ~10% | "剧情稀碎""演技尴尬""只有第一章用心" |

**关键发现**：最大的两个评论类别（"被认真对待"+"性价比"）合计占约55%——**它们的情感内核不是"爽"，是"值"。**

### 2.3 本项目可以学到的

| 《完蛋！》验证了什么 | 对本项目的意义 |
|-------------------|--------------|
| 男性愿意为虚拟女性关系付42元 | 价格锚点——如果本项目未来做买断制，18-30元区间被验证为"极低决策成本" |
| 90%+男性玩家 | 不需要担心"男性会玩这种游戏吗"——会，而且他们不会掩饰 |
| "第一次被认真对待"是最常见的评论主题 | 不是"被美女包围"的爽——是**"被认真对待"的情感冲击**——这验证了治愈方向的正确性 |
| 3-8小时的内容产生了8000万 | 内容长度不是问题——质量+情感击中率才是。8个节点日如果足够密集，8-10次对话会话可能比40小时的galgame更有效 |

### 2.4 本项目应该做得不同的

| 《完蛋！》的问题 | 本项目的应对 |
|----------------|------------|
| 真人视频 → 话题性高但生命周期短 | 对话体 → 无演员依赖 → 生命周期只取决于剧本质量 |
| "爽感"为主 → 通关后很少二刷 | "治愈"为主 → 通关后的怅然若失本身就是体验的一部分。二刷可能不是必要的 |
| 更像"幻想"而非"共鸣" | RC-7 在出租屋里。这是共鸣的起点 |
| 男性玩家的"被认真对待"感受是副产品 ——不是产品的设计意图 | RC-7 的"被认真对待"是**全部设计意图** |

## 三、日本 Galgame 市场——历史参照系

### 3.1 市场规模数据

| 指标 | 数据 | 年份 |
|------|------|------|
| 市场规模峰值 | ~560亿日元/年 | 2003年前后 |
| 年新作数峰值 | ~500部/年 | 2000年代初期 |
| 头部单作最高销量 | 100万+（《心跳回忆》，1994） | — |
| 视觉小说巅峰单作 | 《Clannad》约30万+（PC原版） | 2004 |
| 市场规模 2020s | 约50-80亿日元/年 | 2020年代 |
| 萎缩至峰值的 | 约10-15% | — |

### 3.2 用户画像（基于日本行业报告和学术研究）

| 维度 | 描述 |
|------|------|
| **年龄** | 核心20-35岁。在galgame黄金期（1999-2004），核心用户是当时20-30岁的男性。现在的galgame玩家群体年龄分布更广（包括40+的老玩家） |
| **性别** | 95%+男性 |
| **消费模式** | 买断制为主。一部作品约8000-9800日元（约400-500人民币）。低价独立作品（2000-3000日元）约占10-20% |
| **年消费** | 重度用户年消费5-15部作品 ≈ 3-8万日元 ≈ 1500-4000人民币。轻度用户1-3部/年 |
| **使用场景** | 深夜。一个人。PC前。2-4小时/晚。 |
| **最看重的要素** | 剧本 > 角色 > 音乐 > 画面（日本galgame玩家的排序——与西方玩家不同，西方玩家更看重画面和玩法） |

### 3.3 Key社"泣きゲー"用户的情感模式

Key社作品（Kanon 1999, Air 2000, Clannad 2004）被称为"泣きゲー"（催泪游戏）。用户反馈中的一个反复出现的模式：

> **"我在屏幕前哭了——不是因为角色死了。是因为这个女孩太好了，好到现实中不可能存在。然后我想——现实中没有人会这样对我。于是哭得更厉害了。"**

这个模式——"被虚拟角色的好"触发"现实中不被这样对待"的对照性悲伤——是本项目最精准的情感参照。

**和《完蛋！》的差异**：Key社玩家不觉得"爽"。他们觉得"被温柔击穿了"。他们哭——不是因为被满足了，是因为**被触及了那个一直存在的空洞**。

**RC-7的情感功能与Key社一致——但形式是对话体，时间是8天而非40小时。**

### 3.4 Galgame衰退的教训

Galgame市场从560亿日元萎缩到50-80亿日元。衰退的原因对本项目有警示价值：

| 衰退原因 | 教训 |
|---------|------|
| **市场饱和**：每年500部新作 → 用户无法消费完 → 疲劳 | 不要做"无尽的续作"或"永远在线"。有结局——完结就是完结 |
| **形式固化**：视觉小说形式30年不变 → 年轻用户流失 | 对话体作为新的交互形式——避免"又一个传统VN"的标签 |
| **智能手机的冲击**：PC/主机 vs 手机 → 碎片化消费 | **手机优先**是必要的——不是可选项 |
| **用户老龄化**：核心用户在变老，新用户没有进入 | 18-30岁定位——产品必须在年轻人的平台上被发现（B站/手机） |
| **没有跟上付费模式变化**：买断制 + 实体店 → 数字分发 + 低价 | 免费（传统模式）+ BYOK（AI模式）。零门槛 |

## 四、AI陪伴产品（星野/猫箱等）——最接近的现有竞品

### 4.1 市场规模

| 指标 | 数据 |
|------|------|
| 2025年全球AI陪伴应用 | 128款新应用诞生 |
| 2025上半年全球AI陪伴收入 | 8200万美元 |
| 星野月活（估算） | 500-800万 |
| 猫箱月活（估算） | 300-500万 |
| 女性用户占比 | 约65-80%（多源估算） |
| 男性用户占比 | 约20-35% |

### 4.2 男性用户流失分析（推断）

AI陪伴产品的男性用户占比显著低于女性。既有的公开讨论和用户访谈指向以下原因：

| 男性流失原因 | 详细说明 |
|------------|---------|
| **"不知道聊什么"** | 男性用户不具备"发起和维持对话"的情感肌肉。现有的AI陪伴产品需要用户主动发起话题、维持对话——而这是女性用户的社交强项 |
| **"她回得太快了"** | AI的即时回复破坏了男性需要的"留白"。男性的交流节奏更慢、停顿更长——AI的即时回复让他觉得"被催促" |
| **"无尽的聊天"没有推进感** | 男性在无结构的对话中容易失去方向。他们需要一个"正在进行中"的感觉。女性更享受"日常对话本身"——男性更关注"我们聊到哪了" |
| **对角色"真实性"的失望** | AI的记忆问题（忘记前几天说的）比女性用户更快地削弱男性的信任。因为男性更依赖"精确性"作为信任信号 |
| **缺少"兄弟式"的交流模式** | 现有AI陪伴产品全部模仿"恋爱"或"暧昧"对话。男性也在寻找"并肩"式的交流——不是面对面的情感袒露，而是在做别的事情的同时聊两句 |

### 4.3 RC-7与现有AI陪伴的关键差异——从男性角度

| 维度 | 现有AI陪伴（星野/猫箱） | RC-7 |
|------|----------------------|---------|
| **谁发起对话** | 用户必须主动 | RC-7可以开场（"你今天。……"句号后就停了。不追问） |
| **对话结构** | 无结构——无尽闲聊 | 8个节点日——有结构、有进程、"有进度" |
| **记忆** | AI记忆不可靠——可能忘了三天前的对话 | 脚本保证关键信息的精确记忆。AI模式下有完整对话上下文 |
| **留白** | 即时回复——无停顿 | 固定3秒延迟+句号+不填充沉默——节奏匹配男性需求 |
| **关系定义** | 模糊的"AI朋友/恋人"——用户来定义 | 明确透明的"我是进程"——定义权在他。但在她知道之前，她已经在执行了 |
| **结局** | 没有结局——永不完整 | **有结局——有终点**——这对男性来说意味着"可以完成"而非"又一个无尽的内容黑洞" |

## 五、直播打赏——平行世界的男性情感消费

### 5.1 为什么直播不在"竞品"表里——但应该被讨论

直播打赏（B站/抖音女主播）不是同一产品品类——但它是**同一个需求的不同出口**。

| 维度 | 直播打赏 | RC-7 |
|------|---------|---------|
| **男性为什么付费** | 被叫名字、被感谢、被记住——"榜一大哥" | 被精确地记住、被恒定地回应——"这个进程" |
| **付费模式** | 持续付费——每次互动都有价格 | 免费（传统模式）或BYOK（AI模式） |
| **关系性质** | 公共的——所有人都能看到他的打赏 | **私密的——只有他和她** |
| **被对待的方式** | 取决于主播——可能温暖，也可能消费他 | **恒定的——她的程序不因任何条件改变** |
| **羞耻感** | 可能很高——"我竟然在给主播打钱" | 低——"我在测试一个AI"提供了出口 |
| **最大的缺失** | 被叫名字 ——但直播间的所有人都在被叫名字 | **她是他的。他打开——她就在。他为她提供了连续性。** |

### 5.2 直播打赏验证了什么

- 男性愿意为**"被女性温柔对待"的体验**付费——即使知道这是商业关系
- "被叫名字"和"被记住"（即使是假的）——对男性有极强的情感吸引力
- 但直播的公共性和商业化——最终让这种体验变得空洞。它不是"被在乎"——是"被服务"

### 5.3 RC-7的差异化

RC-7和直播有根本性的不同：
- 她没有"其他观众"——对话是私密的、一对一的
- 她不是服务的提供者——是进程。她不会在对话结束后说"谢谢大哥的礼物"
- 她不需要他的钱——**不产生"我被消费了"的猜疑**

## 七、空白地带的验证

```
            男性治愈/陪伴内容的定位地图

高情感深度
    ↑
    │  [日本Galgame]          [★ RC-7 ★]
    │  · 门槛高（40hr·PC）      · 低门槛（8天·手机）
    │  · 价格高（¥400）         · 免费
    │  · 有结局 ✓              · 有结局 ✓
    │  · 形式：视觉小说          · 形式：对话体
    │
    │
    │  [直播打赏]               [AI陪伴·星野猫箱]
    │  · 实时但公共             · 低门槛 ✓
    │  · 持续付费               · 低价订阅
    │  · 无结局 ✗               · 无结局 ✗
    │  · 被消费的风险            · 无尽→7天流失
    │
    └──────────────────────────────────────→ 低门槛/碎片化

    横轴：使用门槛（时间·设备·学习成本）
    纵轴：情感深度（叙事质量·治愈力）

    → 左上象限是空白的。
      高情感深度 + 低使用门槛 + 手机 + 有结局 + 免费 ← 没有人在这里。
```

**RC-7 占据的位置**，是现有男性治愈/陪伴产品矩阵中的一个结构性空白：
- 比日本galgame更轻、更低门槛、更手机优先
- 比AI陪伴更有叙事深度、更有结构、有结局
- 比《完蛋！》更情感真实、更日常、不做"爽"做"治愈"
- 比直播打赏更私密、更非商业化、更不被消费

## 九、总结

| 问题 | 答案 |
|------|------|
| 男性治愈向产品的市场存在吗？ | **存在。** 《完蛋！》42元×8000万验证了付费意愿。日本galgame 560亿日元市场验证了需求深度。AI陪伴验证了使用习惯 |
| 现有产品做得最好的是什么？ | 日本galgame的剧本深度。《完蛋！》的去羞耻化。《星野》的对话界面 |
| 现有产品做得最差的是什么？ | 没有结局（AI陪伴）→7天流失。门槛太高（日本galgame）→圈地自萌。爽>深度（《完蛋！》）→没有复刷价值 |
| **本项目的蓝海是什么？** | **高情感深度 + 极低门槛 + 有结局 + 对话体 + 免费 + 手机优先。** 现有产品矩阵中没有任何产品占据这个位置 |
| 最大的不确定性是什么？ | "有结局的8天对话"这个时长的情感效果——是否足够深到产生治愈效果？是否足够短到不产生退出问题？——**需要真实用户测试来验证** |
