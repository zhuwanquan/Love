## 二、剧本与叙事架构

这是整个游戏最重要的一层。没有剧本，其他一切都没有意义。

### 2.1 剧本的最小单位：脚本行

传统 VN 的剧本由一系列**脚本指令**组成，每一行是一个指令：

```
# 一个典型的 VN 脚本片段

[背景 宿舍_夜晚]
[音乐 bgm_静夜]
[角色 机器人 位置=右 表情=默认]

机器人：「晚上好。今天的课程内容都理解了吗？」

[选择]
  → 「理解了，谢谢。」          # 跳转到 label_复习完成
  → 「还有些地方不太懂……」      # 跳转到 label_继续辅导
  → （沉默）                    # 跳转到 label_沉默分支

[label label_复习完成]
机器人：「很好。如果有疑问，随时可以问我。」
[跳转 label_夜晚结束]

[label label_继续辅导]
机器人：「没关系。我们再来一遍。哪个概念你觉得最困难？」
# ……
```

### 2.2 脚本指令类型完整清单

| 指令类型 | 说明 | 示例 |
|----------|------|------|
| **对话** | 角色说一句话 | `机器人：「你好。」` |
| **旁白/叙述** | 叙述性文字（无说话者） | `窗外的雨声持续了一整夜。` |
| **背景切换** | 更换场景背景图 | `[背景 教室_白天]` |
| **角色出现** | 角色立绘进入画面 | `[显示 机器人 位置=右 表情=微笑]` |
| **角色消失** | 角色立绘退出画面 | `[隐藏 机器人]` |
| **角色表情** | 切换角色立绘表情 | `[表情 机器人 疑惑]` |
| **音乐** | BGM 切换 | `[音乐 bgm_日常]` |
| **音效** | 播放音效 | `[音效 sfx_敲门]` |
| **选择** | 弹出选项给玩家 | `[选择] → 选项1 → 选项2` |
| **跳转** | 无条件跳转到标签 | `[跳转 label_xxx]` |
| **条件跳转** | 满足条件才跳转 | `[如果 好感>=5 跳转 label_好结局]` |
| **变量操作** | 修改变量值 | `[设置 好感 +1]` |
| **标签** | 脚本中的锚点 | `[label 某处]` |
| **等待** | 暂停一段时间 | `[等待 1.5s]` |
| **屏幕效果** | 淡入淡出、震动等 | `[淡入 1s]` `[淡出 1s]` |
| **章节标记** | 存档用的章节名 | `[章节 第一章·相遇]` |
| **注释** | 不会被执行的说明 | `# 这里是注释` |

### 2.3 剧本的结构层级

```
整个游戏
  └── 章节/节点日（Chapter/Day）
        └── 场景（Scene）—— 一个连续的地点+时间
              └── 脚本块（Block）—— 一组连贯的对话/叙述
                    └── 脚本行（Line）—— 单条指令

例如本项目：
  游戏《RC-Edu-7》
    └── 节点日1：激活
          ├── 场景1.1：宿舍·收到快递（傍晚）
          │     ├── 旁白：收到快递的叙述
          │     ├── 机器人首次启动
          │     └── 第一次对话
          ├── 场景1.2：宿舍·初次交谈（晚上）
          │     └── ……
          └── 场景1.3：宿舍·入睡前（深夜）
                └── ……
    └── 节点日2：……
```

### 2.4 分支叙事的四种模式

**模式 A：纯线性（Kinetic Novel）**
```
场景1 → 场景2 → 场景3 → 场景4 → 结局
```
无任何选项，纯阅读体验。适合强烈作者表达的故事。

**模式 B：分支选择（Branching）**
```
场景1 → [选择] → 场景2A → 场景3A → 结局A
               → 场景2B → 场景3B → 结局B
```
每个选择走向不同的场景线。**最经典的文字恋爱模式**。

**模式 C：Flag 累积（Flag-based）**
```
场景1 → 场景2 → [选择1] → 场景3 → [选择2] → …… → 结局判定
                好感+1              好感+1
                
结局 = 好感>=8 → 好结局
       好感4-7 → 普通结局
       好感<4  → 坏结局
```
选择不直接分叉，而是累积数值，最后统一判定。**适合多角色攻略的游戏**。

**模式 D：混合（Flag + 关键分支）**
```
日常场景（Flag累积） + 关键场景（硬分支）

日常中玩家选择影响好感度
关键节点（如"你选择相信他吗？"）直接分叉到不同剧情线
```

### 2.5 本项目推荐的分支模式

基于你们的节点日结构，推荐 **模式 D（混合）**：

- **节点日内对话**：用 Flag 累积追踪关系值（信赖、亲密度等）
- **节点日之间的过渡叙事**：线性推进，不受选择影响
- **结局判定**：在最后节点日，根据累计 Flag + 关键选择决定结局
- 这样同时保证了"日常的自由感"和"关键时刻的戏剧张力"

## 四、对话系统

### 4.1 对话的显示流程

```
1. 引擎读取下一行脚本
2. 判断指令类型 → "对话"
3. 提取说话者 + 内容
4. 更新 UI：
   - 名字框显示说话者名字
   - 文本框逐字显示对话内容（typewriter效果）
   - 如果说话者立绘存在，高亮/抖动提示
5. 玩家点击/按键 → 显示完整文本（如果还在逐字动画中）
6. 再次点击/按键 → 进入下一行
```

### 4.2 文本显示的核心功能

```
优先级从高到低：

【必须】
├── 逐字显示（typewriter effect）—— 文字一个字一个字出现
├── 点击加速 —— 点击后立即显示全部文本
├── 点击继续 —— 全部显示后，点击进入下一行
└── 历史回看（Backlog）—— 滚动查看之前的对话

【重要】
├── 文字速度调节 —— 快/中/慢
├── 自动模式 —— 自动推进对话
└── 已读跳过 —— 已读过的文本可以快进

【可选】
├── 语音同步 —— 文字显示与配音同步（如有配音）
├── 文本特效 —— 震动、变色、放大（强调用）
└── 对话日志导出
```

### 4.3 对话引擎伪代码

```typescript
class DialogueEngine {
  private script: ScriptLine[];
  private currentIndex: number = 0;
  private isTyping: boolean = false;
  private typedChars: number = 0;
  private textSpeed: number = 50; // ms per char

  async next(): Promise<void> {
    const line = this.script[this.currentIndex];
    
    switch (line.type) {
      case 'dialogue':
        this.ui.setSpeaker(line.speaker);
        this.ui.setNameColor(line.character.color);
        await this.typewrite(line.text);
        break;
      case 'narration':
        this.ui.clearSpeaker();
        await this.typewrite(line.text);
        break;
      case 'choice':
        this.ui.showChoices(line.choices);
        const selected = await this.ui.waitForChoice();
        this.jumpTo(selected.target);
        break;
      case 'jump':
        this.jumpTo(line.target);
        break;
      case 'bg':
        await this.sceneManager.changeBackground(line.image, line.transition);
        break;
      case 'show_char':
        this.charManager.show(line.charId, line.position, line.expression);
        break;
      // ……
    }
    
    if (line.type !== 'jump' && line.type !== 'choice') {
      this.currentIndex++;
    }
  }

  private async typewrite(text: string): Promise<void> {
    this.isTyping = true;
    this.typedChars = 0;
    
    return new Promise((resolve) => {
      const timer = setInterval(() => {
        if (this.typedChars >= text.length) {
          clearInterval(timer);
          this.isTyping = false;
          resolve();
        } else {
          this.typedChars++;
          this.ui.updateText(text.slice(0, this.typedChars));
        }
      }, this.textSpeed);
    });
  }

  onClick(): void {
    if (this.isTyping) {
      // 快进到全文
      this.finishTyping();
    } else {
      // 进入下一行
      this.next();
    }
  }
}
```

## 五、分支与选择系统

### 5.1 选择的数据结构

```typescript
interface Choice {
  id: string;
  text: string;              // 显示给玩家的选项文字
  target: string;            // 跳转目标标签
  condition?: Condition;     // 显示条件（可选——不满足条件则不显示）
  preview?: string;          // 悬停提示（可选）
}

interface Condition {
  type: 'flag' | 'variable' | 'seen' | 'not_seen';
  key: string;
  operator: '>=' | '<=' | '==' | '!=' | '>' | '<';
  value: number | string | boolean;
}
```

### 5.2 选项的实际脚本示例

```
[选择]
  → 「我相信你。」             [跳转 label_相信]
  → 「……给我点时间想想。」      [跳转 label_犹豫]
  → （一言不发地离开）          [跳转 label_沉默离开] [条件 信赖>=6]
  
  # 第三个选项只在信赖>=6时出现
  # 这本身也是叙事——高信赖时才解锁"沉默表达复杂情绪"的选项
```

### 5.3 选择系统的关键细节

- **选项数量**：通常 2-4 个，超过 4 个会让玩家决策疲劳
- **隐藏选项**：满足特定条件才出现的选项（增加重玩价值）
- **已选标记**：有些游戏会给已选过的选项打勾（方便多周目）
- **时间限制**：部分关键选择可加倒计时（增加紧张感，但不要滥用）
- **默认选项**：超时未选时的 fallback

### 6.3 Flag 的读写

在脚本中操作 Flag：

```
# 设置变量
[设置 trust +1]
[设置 closeness +2]
[设置 deep_talk_count = deep_talk_count + 1]

# 设置标记
[标记 first_night_talk]

# 条件判断
[如果 trust >= 8 跳转 label_高信赖路线]
[如果 unexpected_triggered == true 跳转 label_隐藏结局]

# 复合条件
[如果 trust >= 6 且 closeness >= 5 跳转 label_深度关系]
```

### 6.4 变量系统的实现

```typescript
class VariableStore {
  private vars: Map<string, number> = new Map();
  private flags: Map<string, boolean> = new Map();
  private strs: Map<string, string> = new Map();
  private lists: Map<string, string[]> = new Map();

  // 解析并执行变量操作
  execute(command: VariableCommand): void {
    switch (command.op) {
      case 'set':
        this.vars.set(command.key, command.value);
        break;
      case 'add':
        this.vars.set(command.key, this.getNum(command.key) + command.value);
        break;
      case 'flag':
        this.flags.set(command.key, true);
        break;
      case 'unflag':
        this.flags.set(command.key, false);
        break;
    }
  }

  // 评估条件
  evaluate(condition: Condition): boolean {
    const actual = this.get(condition.key);
    switch (condition.operator) {
      case '>=': return actual >= condition.value;
      case '<=': return actual <= condition.value;
      case '==': return actual === condition.value;
      case '!=': return actual !== condition.value;
      case '>':  return actual > condition.value;
      case '<':  return actual < condition.value;
    }
  }

  // 序列化——存档时调用
  serialize(): string {
    return JSON.stringify({
      vars: Object.fromEntries(this.vars),
      flags: Object.fromEntries(this.flags),
      strs: Object.fromEntries(this.strs),
      lists: Object.fromEntries(this.lists),
    });
  }

  // 反序列化——读档时调用
  deserialize(data: string): void {
    const parsed = JSON.parse(data);
    this.vars = new Map(Object.entries(parsed.vars));
    this.flags = new Map(Object.entries(parsed.flags));
    this.strs = new Map(Object.entries(parsed.strs));
    this.lists = new Map(Object.entries(parsed.lists));
  }
}
```

## 八、存档系统

### 8.1 存档包含的数据

一次存档（SaveData）必须完整记录当前游戏的全部状态，以便读档后完全恢复：

```typescript

  timestamp: number;            // 保存时间
  screenshot?: string;          // 缩略图（base64）
  
  // 进度
  scriptLabel: string;          // 当前脚本位置（标签）
  scriptIndex: number;          // 当前脚本行索引
  chapterId: string;            // 当前章节
  chapterName: string;          // 章节显示名（如"节点日3·深夜"）
  
  // 状态
  variables: Record<string, number>;
  flags: Record<string, boolean>;
  strings: Record<string, string>;
  lists: Record<string, string[]>;
  
  // 场景
  currentBackground: string;
  charactersOnScreen: CharacterState[];
  currentBGM: string;
  
  // 历史
  dialogueHistory: DialogueLine[];  // 最近N条对话（用于回看）
  
  // 统计
  totalPlayTime: number;         // 总游玩时间（秒）
  totalDialogueCount: number;    // 总对话行数
}
```

### 8.2 存档槽设计

```
通常提供：
├── 快速存档（1个槽位，快捷键）
├── 手动存档（10-30个槽位，带截图+时间+章节名）
├── 自动存档（3-5个槽位，关键节点自动保存）
└── 章节存档（每个章节开头自动保存一个，不可覆盖）
```

### 8.3 存储方案

根据目标平台：

| 平台 | 存储方案 |
|------|---------|
| Web | IndexedDB / localStorage |
| Electron | 本地文件系统（`app.getPath('userData')`） |
| Unity | PlayerPrefs + 本地文件 |
| Ren'Py | 自动处理（`%APPDATA%/游戏名/`） |

## 十、音频系统

### 10.1 音频分类

| 类型 | 说明 | 格式 | 循环 |
|------|------|------|------|
| BGM | 背景音乐，每个场景/情绪一条 | mp3/ogg | 是 |
| SFX | 音效（敲门、翻书、系统启动等） | mp3/ogg/wav | 否 |
| Voice | 角色配音（如有） | mp3/ogg | 否 |
| Ambient | 环境音（雨声、教室杂音） | mp3/ogg | 是 |

### 10.2 音频管理

```typescript
class AudioManager {
  private bgmVolume: number = 0.7;
  private sfxVolume: number = 1.0;
  private currentBGM: string | null = null;

  playBGM(name: string, fadeIn: number = 1.0): void {
    if (this.currentBGM === name) return;
    // 当前 BGM 淡出 → 新 BGM 淡入
    this.crossfade(this.currentBGM, name, fadeIn);
    this.currentBGM = name;
  }

  playSFX(name: string): void {
    // 音效是一次性的，不循环
    const audio = new Audio(`sfx/${name}.ogg`);
    audio.volume = this.sfxVolume;
    audio.play();
  }

  stopBGM(fadeOut: number = 1.0): void {
    // 淡出并停止
  }
}
```

## 十二、引擎选型对比

### 12.1 主流引擎对比

| | Ren'Py | Web（自研） | Unity + 插件 | Godot + Dialogic |
|---|---|---|---|---|
| **语言** | Python | TypeScript/JS | C# | GDScript |
| **学习曲线** | 低 | 中 | 高 | 中 |
| **打包平台** | Win/Mac/Linux/Android/iOS | 浏览器 + Electron | 全平台 | 全平台 |
| **社区资源** | 极其丰富 | 需自建 | 丰富 | 中等 |
| **AI模式集成** | 困难（Python生态可行但UI框架受限） | **最容易**（同技术栈） | 可行 | 可行 |
| **授权费用** | 免费MIT | 免费 | 免费（需授权收入超阈值） | 免费MIT |
| **适合场景** | 纯传统VN，快速出成品 | **本项目推荐** | 需要3D/复杂动画 | 开源替代Unity |

### 12.2 本项目推荐：Web 技术栈（自研引擎）

**理由**：

1. **与 AI 模式同技术栈**：传统模式和 AI 模式可以共享 UI 层、场景系统、存档系统——只有对话生成层不同。如果用 Ren'Py 做传统模式，AI 模式还要另起一套代码
2. **Electron 打包 = 桌面应用**：满足"单机运行"需求
3. **TypeScript 类型安全**：脚本解析、状态管理有类型保护，减少 bug
4. **完全可控**：不需要适配第三方引擎的限制

**推荐技术组合**：

```
前端框架：    React / Vue / Svelte（选你最熟悉的）
状态管理：    Zustand / Pinia / 自研 VariableStore
样式：       CSS + CSS Animation（typewriter等效果）
本地存储：    IndexedDB（存档） + localStorage（设置）
音频：       Web Audio API / Howler.js
打包：       Electron（桌面端）/ 纯浏览器（Web端）
脚本格式：    JSON/YAML/自定义DSL → 解析为 ScriptLine[]
```

### 12.3 各引擎的详细评估

#### Ren'Py（最适合纯传统VN快速出成品）

```
✅ 优点：
  - 专为VN设计的DSL，写剧本极其自然
  - 存档/读档/设置/跳过/回看 全部内置
  - 庞大的中文社区和教程
  - 免费，商业友好

❌ 缺点：
  - Python GUI 框架，无法与 Web AI 模式共享代码
  - UI 自定义较困难（默认界面比较"经典"）
  - 移动端打包配置较繁琐

适合：如果你确定传统模式是主要产品，AI模式是附加功能
```

#### Web 自研（最适合本项目双模式共存需求）

```
✅ 优点：
  - 传统模式 + AI模式 共享同一套UI和状态管理
  - 部署灵活：浏览器即用，Electron打包即桌面
  - 完全的控制权——每一个像素都可以自定义
  - 方便后续加多人协作（Web技术栈开发者最多）

❌ 缺点：
  - 所有VN基础功能都要自己写（对话引擎、存档、回看……）
  - 初期开发速度不如Ren'Py
  - 需要额外处理 Electron 打包的细节

适合：本项目——双模式共存，需要对代码库有完全掌控
```

#### Unity + Naninovel/Fungus

```
✅ 优点：
  - 可以混合2D和3D内容
  - 成熟的Asset Store生态
  - 全平台发布

❌ 缺点：
  - VN系统是"插件"，不是原生支持——深度定制时可能碰到限制
  - 与Web/JS生态对接AI模式需要额外桥接层
  - 引擎本身很重（下载体积大、加载慢）

适合：如果你需要VN以外的复杂玩法（如小游戏、3D场景探索）
```

## 附录：最小原型（MVP）究竟有多小

如果只做 **能验证核心假设的最小东西**：

```
需要实现的东西（按顺序）：

1. 一个 HTML 页面
   ├── 一个 div 做背景区域（放纯色背景或一张图）
   ├── 一个 div 做文本框（底部）
   └── 点击事件监听

2. 一段硬编码的剧本数据（JSON数组）
   [
     { type: "narration", text: "快递盒很轻。你拆开它，里面是一台……" },
     { type: "dialogue", speaker: "RC-Edu-7", text: "你好。我是RC-Edu-7。请告诉我你的学习目标。" },
     { type: "choice", choices: [
         { text: "我想学好数学。", next: 3 },
         { text: "我其实……不太确定自己想要什么。", next: 4 }
       ] },
     // ...
   ]

3. 一个 30 行的 JavaScript 引擎
   - 读取当前行
   - 对话 → 逐字显示
   - 选项 → 显示按钮，等点击 → 跳转
   - 点击推进

这就够了。
```

**这个 MVP 可以：**
- 验证剧本节奏是否对
- 验证机器人的人设文字是否有"感觉"
- 给朋友试玩，收集第一波反馈
- 在一天之内搭建完毕

**这个 MVP 不需要：**
- 存档系统（太短了不需要）
- 背景切换（一张图用到底）
- 立绘（纯文字即可）
- 音频（先不加）
- 变量系统（线性跑完即可）
