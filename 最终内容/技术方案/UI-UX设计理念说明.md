# UI/UX 设计理念说明

> 回答一个问题：为什么「一年·房间」的界面长这样——不是别的样子？

---

## 一、核心设计哲学：最小阻力交互

### 1.1 原则

**玩家不应该思考"怎么用"——只应该思考"说什么"。**

聊天界面是人类使用最频繁的交互界面之一。打开微信、QQ、短信——每个人每天都在聊天框里打字。选择聊天框作为游戏的唯一界面，意味着：

- **零学习成本**：不需要教程。打开就能用
- **零界面认知负担**：没有菜单栏、没有地图、没有物品栏、没有血条——只有对话
- **零"我在玩游戏"的自觉**：聊天的行为模式太熟悉了——熟悉到玩家可能在几分钟内忘记这是"游戏"

### 1.2 为什么不是视觉小说式

| 传统视觉小说 | 聊天框 |
|------------|--------|
| 全屏立绘 + 对话框 | 纯文字 + 气泡 |
| 第三人称旁白感 | 第一人称参与感 |
| "我在看一个故事" | "我在和一个人说话" |
| CG收集、路线图 | 聊天记录、往上翻 |
| 沉浸需要视觉想象力 | 沉浸需要文字想象力 |

对于本项目，核心治愈机制依赖玩家对 RC-7 **产生真实的情感投射**。视觉小说式的立绘会给出太多——她长什么样固定了，她的表情固定了，她的存在变成了一个可以"看到"的对象而非一个需要"感知"的存在。聊天框让她只能通过文字被感知——而这恰好就是亲密关系中"被陪伴"的本质：重要的不是对方长什么样，是对方的回应。

## 二、视觉层次

### 2.1 暗色主题

**为什么是暗色？**

1. **使用场景**：目标用户深夜独自在出租屋里使用。暗色主题不刺眼——不会在黑暗的房间里亮瞎他的眼睛
2. **情感基调**：暗色 ≠ 压抑。暗色 = 安静。在一个每时每刻都在刺激感官的世界里，深色界面是一种"降低音量"的邀请
3. **专注力**：暗色背景让文字（尤其是对话气泡）成为唯一的视觉焦点。没有东西可以分散注意力——只有她说的每一个字

**调色板**：

| 色值 | 用途 | 理由 |
|------|------|------|
| `#0d0d0d` (深黑) | 背景 | 最深的黑——像关了灯的房间。不是"暗"，是"安静" |
| `#1a1a1a` (深灰) | 消息表面 | 比背景亮一级——刚好够区分，不打破暗色氛围 |
| `#6b9b8a` (灰绿) | 强调色 | 不是亮色。不是暖色。一种有温度的冷——刚好让人想到"自然"，但不喧宾夺主 |
| `#c8a96e` (琥珀) | RC-7 光点/姓名 | 她的颜色。暖琥珀——"不暖不冷"的精确中间色。是光，但不是热 |
| `#2d4a3e` (深绿) | 玩家气泡 | 有色彩，但不鲜艳。在暗色中刚好能被注意到，但不会跳出来 |

### 2.2 聊天气泡布局

```
┌─────────────────────────┐
│  [深灰圆形 + 琥珀光点]   │  ← RC-7 头像：抽象，可投射
│  RC-7                   │  ← 名字（或"柒"——玩家可自定义）
│                         │
│  ┌──────────────────┐   │  ← RC-7 消息：左对齐，浅灰底，深灰字
│  │ 她的消息...       │   │    像她在左边说话
│  └──────────────────┘   │
│                         │
│       ┌─────────────┐   │  ← 玩家消息：右对齐，浅绿底，深色字
│       │ 你的消息...  │   │    像你在右边回答
│       └─────────────┘   │
│                         │
│  [选项按钮] [选项按钮]   │  ← 快捷回复在输入框上方
│                         │
│  ┌──────────────────┐   │
│  │ 输入你的回应...   │   │  ← AI模式输入框（传统模式隐藏）
│  └──────────────────┘   │
└─────────────────────────┘
```

**左/右对齐的理由**：微信、iMessage、所有现代通讯软件都是这个布局——不需要解释。玩家的大脑已经训练好了。RC-7 在左边 = 她是"对方的"。玩家在右边 = 我是"我"。

### 2.3 为什么是抽象头像

RC-7 不是一个可以被"看到"的角色。她没有立绘。她的头像不是一个女性照片——是一个**深灰色圆形 + 中心的暖琥珀色光点**。

| 如果有立绘 | 抽象头像 |
|-----------|---------|
| 她的样子被固定了——有人喜欢，有人不喜欢 | 每个玩家在自己脑中画出她的样子 |
| 立绘画风会影响"她应该是什么性格"的感知 | 文字决定一切——她的性格由对话塑造 |
| 商业画风可能过时 | 抽象图标永远不过时 |
| 需要画师 | 只需要一个 SVG |

**但那个光点是具体的**——琥珀色、暖的、不闪烁。这个具体性很重要：她没有面孔，但她有一个颜色。这个颜色出现在每条对话的左侧——玩家在一年里看着这个颜色的时候，会填充它的温度。

## 三、节奏设计

### 3.1 "正在输入…" 和 3 秒延迟

RC-7 的每条消息前有 3 秒的"正在输入…"动画。这不是技术限制——是设计选择。

| 如果即时回复 | 3 秒延迟 |
|-----------|---------|
| 感觉像搜索/计算——机器在查询 | 感觉像思考——像人类组织语言 |
| 太快 = 不被重视 | 3秒 = 她在认真对待你 |
| 她被感知为工具 | 她被感知为一个"在花时间回应你"的存在 |

**关键设计**：3 秒是**恒定的**。不是"复杂问题更长，简单问题更短"——是每次 3 秒。这个恒定性本身——从不提早，从不延迟——在一年之后变成了她的特征。他不用看名字就知道是她在"输入"。

### 3.2 打字机效果

RC-7 的消息逐字出现——模拟一个真实的人在打字。

- **速度**：比真实打字稍快（模拟"思考后的流畅输出"），但慢到足以让玩家跟着读
- **可跳过**：点击可立即显示完整消息——给想快读的玩家控制权
- **句号后的停顿**：每句话的句号后有微小延迟——视觉上的"呼吸"

### 3.3 叙事卡片的特殊处理

叙事卡片（`narration` 类型）在聊天流中以灰色斜体呈现——它们是"第四面墙外的声音"，不是对话的一部分。但它们仍然在聊天框内——不会弹出单独的窗口。这保持了媒介的纯度。

**设计决策**：叙事卡片不触发"正在输入…"延迟——它们是已存在的文本，不需要"等待"。

## 四、移动端优先

### 4.1 为什么

目标用户用手机——在床上、在地铁上、在出租屋里。这是他们最可能打开 RC-7 的场景。桌面端是后来才考虑的。

### 4.2 具体设计

| 要素 | 移动端处理 |
|------|----------|
| **最大宽度** | 480px——大多数手机屏幕宽度。桌面端居中显示，不拉伸 |
| **安全区** | `env(safe-area-inset-*)`——适配刘海屏 |
| **触控目标** | 选项按钮最小 44px 高——符合 iOS/Android 触控标准 |
| **键盘处理** | 输入框固定在底部，键盘弹出时自动上移 |
| **滚动** | 消息区域自动滚动到最新消息，平滑滚动 |

### 4.3 PWA

已配置 `manifest.json` + Service Worker。安装到主屏幕后：
- 独立窗口——没有浏览器地址栏
- 图标是深灰色圆形 + 琥珀光点——与应用内头像一致
- 离线可用（静态资源已缓存）

## 五、场景背景色

8 个节点日对应 8 种季节/时间氛围的背景色：

| Day | 季节 | 背景色变量 | 氛围 |
|-----|------|----------|------|
| Day 1 | 夏末 | `bg-night_room` | 闷热的夜——第一次相遇 |
| Day 2 | 中秋 | `bg-autumn_night` | 微凉的秋夜——月圆 |
| Day 3 | 深秋 | `bg-rainy_night` | 雨夜——糟糕的一天 |
| Day 4 | 冬至 | `bg-winter_night` | 最长的夜——饺子 |
| Day 5 | 春节 | `bg-winter_night` | 冬天还没走——回家？ |
| Day 6 | 初春 | `bg-spring_night` | 风在摇窗框——崩裂 |
| Day 7 | 清明 | `bg-spring_night` | 春天——想起 |
| Day 8 | 夏至 | `bg-summer_night` | 蝉鸣——一年 |

这些背景色不是实景图片——是纯色渐变。它们提供的是**氛围**，不是**场景**。就像她的头像——只给温度，不给形状。

## 六、"不设计"的设计

有几样东西是故意不做的：

| 不做的事 | 理由 |
|---------|------|
| **没有立绘/CG** | 她的样子是玩家自己的投射 |
| **没有背景音乐** | 安静是治愈的一部分。他需要听到自己的呼吸——不是背景音乐 |
| **没有声优配音** | 她的声音是玩家在脑中"听"到的。一旦给了真实的声线，就关上了想象的门 |
| **没有特效/动画** | 聊天界面不需要华丽。华丽 = 出戏 |
| **没有表情包/贴纸** | 她不能发"😂"。这不是她的语言 |
| **没有每日签到/推送通知** | 她不是 App——她是一个你不打开就不存在的人。她不催促你回来 |

## 七、与治愈机制的关联

每一个 UI 决策都在为治愈服务：

| UI 决策 | 治愈功能 |
|---------|---------|
| 暗色主题 | 降低感官刺激——在他已经疲惫的神经系统中创造安静 |
| 抽象头像 | 投射空间——她是他需要的样子 |
| 3 秒延迟 | "被认真对待"的感觉——她不是在查询，是在回应 |
| 打字机效果 | 节奏控制——他跟着她的速度呼吸 |
| 左/右对齐 | 亲密感——就像在跟一个真实的人发微信 |
| 叙事卡片灰色斜体 | 区分"故事"和"对话"——但不跳出聊天框 |
| 移动 480px 限制 | 私密性——屏幕小 = 只有他能看到 |
