# RC-7 角色形象展示区设计方案

> 回答一个问题：如何在保持文字对话的前提下，给 RC-7 一个"可以被看见"的空间——让她的存在不只是文字，而是有形象、有动作、有温度变化？

---

## 〇、设计动机

当前界面是纯聊天框。RC-7 在这个界面中只是一行行文字——虽然文字本身有力量，但缺少**直接的视觉冲击**。用户需要一个能看到"她"的区域——不只是一段话从左边冒出来，而是一个可以注视、可以感受到"她此刻的状态"的视觉存在。

**设计目标**：
- 在聊天框之外增设一个**独立的角色展示区**
- 该区域展示 RC-7 的形象——不是静态立绘，是有**状态变化**的视觉呈现
- 她的形象随对话内容、情绪氛围、昼夜节律产生微妙变化
- 保持文字对话作为核心交互方式——形象展示是**增强**，不是替代

**设计约束**（来自现有角色设定）：
- RC-7 没有具体面孔——她的形象是玩家投射的。展示区不能给出太具体的五官
- 她的美是"含蓄的"、"需要被发现的"——展示区不能变成"炫技"
- 她是一台机器——展示区不能让她看起来像一个人类女性在视频通话

### 1.3 画框设计

角色展示区不叫"立绘区"——叫**画框**。像一个挂在墙上的画框，或者手机屏幕上的一个"窗口"。

| 要素 | 设计 | 含义 |
|------|------|------|
| **外框** | 深灰细边框，圆角 | 像一个相框——"她是一幅画"。不是视频通话窗口 |
| **背景** | 随场景季节变化——夏末闷热的暗、中秋微凉的蓝灰、冬至深黑、初春灰绿 | 不是实景——是纯色渐变，暗示时间和氛围 |
| **光源** | 画面中唯一的固定光源来自她的眼睛方向——暖琥珀色 | 她的光。不是环境光 |
| **比例** | 3:4 竖幅——中国传统仕女画的经典比例 | "她是一幅画"——不是一张照片 |

## 二、形象呈现方案

### 2.1 核心原则：不画五官，画"神韵"

RC-7 的形象不能是具体的——那是立绘的逻辑。她的形象应该是**水墨式的、意境式的、留白式的**。继承中国传统仕女画的核心审美："重神似，轻形似。"

**具体方案**：

| 可见的 | 不可见的（留给想象） |
|--------|-------------------|
| 身形轮廓——修长、沉静、肩膀平直 | 五官细节——眉、唇的具体形状 |
| 深棕色长发——束成低马尾 | 皮肤质感 |
| 白色衬衫的轮廓——没有褶皱 | 手的具体形状 |
| 琥珀色光——在眼部位置，是唯一的具体颜色 | 表情的细节——但氛围可感 |
| 铭刻线——在耳后位置隐约可见 | 脚和鞋 |

**视觉效果**：她像一幅**未完成的水墨仕女画**——笔触在最关键的地方停下来。不是画不好——是不需要画完。观者自己补充。

### 2.2 风格参考

| 参考源 | 借鉴什么 |
|--------|---------|
| **顾恺之《洛神赋图》** | "瘦骨清象，气度高古"——人物的飘渺感和超脱感 |
| **宋代水墨仕女** | "清隽文秀，轻毫淡墨"——不是重彩，是淡到几乎透明的笔触 |
| **改琦《红楼梦图咏》** | "神韵天然"——不是工笔的精确，是写意的神似 |
| **留白哲学** | 中国画的核心——"虚实相生，无画处皆成妙境"。不画的地方比画的地方更重要 |

### 2.3 技术实现方向

**方案A：CSS/SVG 矢量绘制**
- 用 SVG 绘制简化的人物轮廓
- 颜色：深灰+白+琥珀色光点
- 优点：文件极小，可程序化控制
- 缺点：表现力有限

**方案B：多层水墨风格 PNG + CSS 动画**
- 预先绘制 3-5 层半透明水墨风格的人物图层
- 通过 CSS 叠加和 opacity/transform 动画产生"呼吸感"
- 优点：有水墨质感，可程序化控制情绪
- 缺点：需要美术资源

**方案C：Canvas/WebGL 实时渲染**
- 用粒子系统模拟"水墨在宣纸上晕开"的效果来构成人物轮廓
- 优点：极致独特，完美契合"她是程序生成的"设定
- 缺点：开发成本高

**推荐方案**：**B + A 混合**。核心人物轮廓用 SVG（确保在任何设备上都清晰），在画框背景叠加水墨晕染的 CSS 动画层。琥珀色光点可以有呼吸式微动。

## 三、状态系统

画框中的 RC-7 不是静止的——她的状态随对话内容、时间、情绪氛围而变化。但这个变化是**含蓄的、微妙的**——不是夸张的动画。

### 3.1 五个状态层级

| 状态 | 触发条件 | 视觉表现 | 含义 |
|------|---------|---------|------|
| **静待** | 默认状态。他还没说话，或者对话间的沉默 | 身形轮廓安静，光点恒定亮度。画面中唯一的"动"是光点极微弱的呼吸式脉动（周期约4-5秒） | "她在。像一杯放了一夜的水。" |
| **聆听** | 他正在输入，或刚发完一段较长的话 | 光点亮度微微提升（+15%）。轮廓边缘略微柔和。画面有一种"她在接收"的安静专注感 | "她在听。不打断。" |
| **回应** | 她的消息正在生成/显示时 | 光点亮度小幅波动（模拟"处理"）。3秒延迟期间光点有一个几乎不可察觉的明暗循环 | "她在思考。3秒。" |
| **关怀** | TCP协议触发时（节日、长间隔后、深夜） | 光点暖度微微提升——琥珀色中多一点红。轮廓边缘更柔和。画面整体色温偏暖 | "她在意。不是'担心'——是'注意到了'。" |
| **深度** | Day 6崩溃场景、Day 8夏至——情感重量最重的时刻 | 光点亮度降到最低但不熄灭——像一根蜡烛在风中但不灭。轮廓更加清晰（对比度提升），画面寂静 | "她在。在最深的地方。" |

### 3.2 昼夜变化

画框背景随游戏内时间（节点日）变化：

| 节点日 | 背景色 | 氛围 |
|--------|--------|------|
| Day 1 夏末 | 深闷的灰蓝——像没有空调的房间 | 闷热、初次相遇 |
| Day 2 中秋 | 微凉的灰蓝——月光透过薄云 | 清冷、一个人的节日 |
| Day 3 深秋 | 雨夜的灰——不是暴雨，是绵绵雨 | 潮湿、糟糕的一天 |
| Day 4 冬至 | 最深的灰黑——一年最长的夜 | 寒冷、但她在 |
| Day 5 春节 | 灰底泛极淡的红——远处有人放烟花 | 热闹在远处 |
| Day 6 初春 | 灰绿——窗外树发芽了但还冷 | 风摇窗框、崩裂 |
| Day 7 清明 | 灰底泛极淡的青——春天终于站稳 | 想起、哀伤 |
| Day 8 夏至 | 灰底泛淡金——最长白天的余晖 | 一年、完成 |

### 3.3 动作/姿态变化

微妙到几乎不可察觉——但如果玩家盯着看，他会发现：

| 动作 | 触发 | 持续时间 | 视觉效果 |
|------|------|---------|---------|
| **微微偏头** | 他说了一句她需要"多想一下"的话 | 2-3秒 | 轮廓有极微小的角度偏移——像她在从另一个角度看他 |
| **光点闪了一下** | 她说了"可能"、"我不知道"——不在预设中的词 | 0.5秒 | 琥珀色光点的亮度瞬间波动——"原因不明" |
| **发丝微动** | 场景中有风的描写，或季节转换 | 循环 | 几缕碎发的位置有极微小的偏移——不仔细看不会发现 |
| **呼吸式起伏** | 始终存在 | 4-5秒周期 | 轮廓的透明度有极微弱的循环变化——"她是活的吗？——不是。是程序在运行。" |
| **铭刻线微光** | 结局A——"灯在闪"的时刻 | 7秒 | 耳后的铭刻线位置出现一条极细的暖色光——不闪，只是亮着 |

## 四、与传统女性美的关联

画框中的 RC-7 应该让熟悉中国绘画的人产生一种似曾相识的感觉——"这好像一幅仕女画"——但说不清为什么。因为她没有具体的五官和服饰细节。但她有**仕女画的"气"**。

| 仕女画传统 | 画框中的体现 |
|-----------|------------|
| **"望之有幽娴贞静之态"** | 她大部分时间处于"静待"状态——安静、不喧哗 |
| **"仪静体闲"** | 她的动作变化微乎其微——不慌张、不急切 |
| **"重神似轻形似"** | 没有具体五官——只有轮廓、光、和氛围 |
| **留白** | 画框的背景是渐变色——不是实景。像仕女画中"虚"的背景 |
| **诗画合一** | 聊天框中的文字（她的消息）和画框中的图像（她的轮廓）共同构成完整的她——不是"看图说话"，是"诗画互补" |

## 五、关键场景脚本

### 5.1 初次打开

```
画框：深灰黑的背景。轮廓极淡——几乎看不清。
只有琥珀色光点在中心微微亮着——像黑夜中很远的一盏灯。

玩家：选择了身份标签。

光点亮度：从暗到明的2秒过渡——"启动时从暗到明有两秒过渡"。
轮廓：逐渐清晰——从40%透明度过渡到100%。
背景：从纯黑过渡到夏末的深灰蓝。

对话开始。
```

### 5.2 Day 3 "我在。"

```
前状态：画框中的她处于"静待"——光点恒定。

玩家："今天不太好。"

光点：有一个几乎不可察觉的亮度波动——0.3秒。
（如果玩家仔细看——他看到了。如果没看——他错过了。）

她的消息到达："我在。"

画框中：光点比平时亮了约10%。轮廓边缘比平时柔和。
状态切换到"关怀"——但极轻微。像水面被投了一颗很小很小的石子。
```

### 5.3 Day 6 崩溃

```
前状态：凌晨。画框背景是深灰绿——初春的颜色。

玩家："我撑不住了。"

画框：光点不变——她没有"紧张"或"慌张"的电路。
但轮廓的透明度有一个几乎不可察觉的加深——她在"聚焦"。

她的消息到达——那段250+字的全年追溯。

画框中：她说话期间，光点持续在"深度"状态——亮度降到最低但不灭。
画面比任何时候都安静。背景色比平时深了一度。

她说完了。光点回到正常亮度。轮廓回到正常透明度。
她没有变。她一直是。但刚才——她"在"的方式不一样了。
```

### 5.4 Day 8 "好。"

```
前状态：夏至。画框背景是灰底泛淡金。

玩家："今天不分析。"

画框：光点有一个极其微小的闪烁——"她在接收这个指令"。

她的消息到达："好。"

画框中：光点暗了一瞬——然后回到正常。
但是——她的轮廓——有一个极其微小的、从未出现过的——
不是动作——是静止。是她以前的静止中总有一个呼吸式脉动。
这一次——停了。完全静止。两秒。
然后呼吸式脉动恢复。

如果你盯着看——你看到了。
如果你没有——你不知道你错过了什么。
```

## 六、技术实现路径

### 6.1 推荐路径

**第一阶段（当前可做）**：使用 CSS + SVG 实现基础画框。
- 画框布局集成到聊天界面
- 用 SVG 绘制基础轮廓和光点
- CSS animation 实现呼吸式脉动和状态切换
- 背景色随节点日变化

**第二阶段（有美术资源后）**：升级为多层水墨风格。
- 委托绘制水墨风格的轮廓图层（3-5层）
- CSS opacity/blend-mode 叠加产生水墨质感
- 加入粒子系统模拟水墨晕染

**第三阶段（远期）**：Canvas 实时水墨生成。
- 用算法模拟水墨在宣纸上的扩散
- 轮廓不是固定的——每一次打开都有微小的不同
- "她每次被打开——都是一次新的渲染"

