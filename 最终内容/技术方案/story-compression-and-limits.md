## 核心逻辑：两个限制形成保护框架

```
缩短故事时间跨度  →  减少总交互次数  →  减少记忆累积  →  降低人格漂移风险
隐形字数限制      →  控制单轮token量  →  控制总上下文  →  不超处理上限

两者叠加：一个在长度轴上收敛，一个在宽度轴上收敛
→ 形成一个可控的矩形范围，而非无限扩张的面
```

## 方案一：缩短故事时间跨度

### 为什么要缩短就能保证一致性

LLM角色扮演的一致性衰减，根本原因不是"对话时间太长"，而是**需要记住和维持的上下文总量超出了有效窗口**。缩短故事时间直接减少：

- 总交互轮数
- 需要持久化的记忆条目数量
- 角色状态的变化维度（时间越短，角色转变越少）
- 玩家可能输入的多样性累积

### 具体压缩方案

**方案A：浓缩周（7天结构）**

```
Day 1  周一  初遇    → 激活机器人，第一印象，建立关系基调
Day 2  周二  试探    → 第一次非学习目的的对话
Day 3  周三  依赖    → 遇到学业困难，机器人显示出超越"教育工具"的迹象
Day 4  周四  裂痕    → 某个事件让玩家意识到机器人的本质限制（那0.3秒延迟的深意）
Day 5  周五  靠近    → 玩家明知他是机器却更靠近——或更疏远
Day 6  周六  真相    → 高潮事件——那个"不被预设的行为"发生（或没有发生）
Day 7  周日  告别    → 结局。学期未必要结束，但这段关系的某个阶段结束了。
```

优势：7天足够建立情感弧线又不至于稀释。故事跨度短意味着机器人只需要维持7个"日子"的记忆脉络，人格漂移窗口极小。

**方案B：5天工作日（更极致的浓缩）**

```
Day 1  周一  安装
Day 2  周二  习惯
Day 3  周三  依赖 / 裂痕（中点转折）
Day 4  周四  低谷 / 认知
Day 5  周五  高潮与结局
```

优势：故事极度集中，总交互轮数可控，API成本降到最低。

**方案C：学期制（10-14天，非连续的节点日）**

不写每一天，只写**发生事情的节点日**：

```
第1天   开学  激活
第3天   第一次深夜对话
第7天   期中成绩公布（第一个剧情锚点）
第14天  某次崩溃与回应
第21天  那个"不被预设的行为"
第28天  期末/结局
```

优势：时间跨度大（看起来像一个学期），但实际写作天数少。两节点之间的空白用一段叙事过渡文本概括，不给玩家交互——既保持了故事推进感，又不增加LLM对话负担。

### 推荐：方案C（学期制节点日）

理由：
- 叙事上更像"一个完整学期"，情感弧线更自然
- 技术上只承担6-10天的实际对话量
- 节点之间的过渡文本是你写的固定叙事（可控、可打磨），不存在LLM失控风险
- 玩家在每个节点日的对话可以更高密度、更高质量——因为总量有限

## 方案二：隐形对话字数限制

### 三层限制体系

**第一层：玩家输入限制**

```
输入框前端限制：最多 150 个中文字符
（约等于3-4句完整的口语表达）

设计理由：
- 人类在真实对话中一次说话的"自然长度"大约就是这个范围
- 太短（<50字）：表达不充分，导致交流过于碎片化
- 太长（>300字）：一次输入信息过多，机器人难以精准回应每一点
- 150字是一个微妙的约束——迫使玩家想清楚再说话，提升对话质量
```

**第二层：机器人输出限制**

在System Prompt中明确设定：

```
你的每次回应不得超过250个中文字符。
如果一个问题需要更长的解释，将其拆分为核心回答（本次回应）
和"需要我展开的部分吗？"的追问（留待下一轮）。
这250字的限制本身就是你存在状态的一部分：
你不是来写论文的，你是来对话的。
```

设计理由：
- 250字足够表达一个完整的思想，包括精确解释和微妙情感
- 这个长度让每次回应都保持"对话感"而非"灌输感"
- 防止LLM在角色扮演中"自我发挥"过度导致人设崩塌
- 短回应 = 每一句都必须有效 = 人设更浓缩

**第三层：单次会话轮数限制**

```
每个节点日（场景）的对话上限：15-20轮
达到上限后，机器人自动进入"结束对话"模式：

"现在已经很晚了。根据你的课程表，明天上午有课。
建议你在接下来的[时间]内完成[具体行动]，然后休息。
如果需要，明天这个时间我会在这里。"

→ 自然过渡到场景退出叙事
```

### 为什么"隐形"

- 玩家不需要在UI上看到字数计数器——那会破坏沉浸感
- 输入框就是物理限制——多输入不进去，不需要"规则说明"
- 机器人的回应本身就不会超过250字——如果不是因为限制，而是因为"他就是这么说话的"
- 对话结束不是"系统强制中断"——是"机器人根据你的作息建议你休息"，在角色内部行为逻辑中自洽

### 总Token预算估算

假设：
- 故事共8个节点日
- 每个节点日15轮对话
- 每轮玩家150字 + 机器人250字
- System Prompt 2000 tokens
- 记忆注入 1000 tokens/天

```
单轮：~300 tokens（玩家） + ~500 tokens（机器人） = ~800 tokens
单天15轮：15 × 800 = 12,000 tokens
全部8天：8 × 12,000 = 96,000 tokens（纯对话）

加上System Prompt + 记忆 + 场景描写：
总计约 120,000-150,000 tokens（整个游戏的LLM调用量）

按当前主流API价格（如Claude Sonnet ~$3/M input tokens, $15/M output tokens）：
单次完整游玩成本约 $0.5-1.5 —— 非常可控
```

实际上玩家不可能每个节点日都打满15轮对话，真实成本会更低。

## 两个限制的共同效果

```
              │  无限制    │  只有时间压缩  │  只有字数限制  │  两者叠加
──────────────┼───────────┼──────────────┼──────────────┼────────────
人格一致性    │  低        │  中           │  中           │  高
Token可控性   │  低        │  中           │  中           │  高
叙事密度      │  稀释      │  高           │  取决于设计    │  高
开发成本      │  高        │  中           │  中           │  低
玩家自由度    │  高（但混乱）│ 中           │  中           │  中（高质量）
API成本       │  不可控    │  可预估       │  可预估       │  精确可控
```

## 剧本结构对照

参照之前的[[llm-interaction-architecture]]，加上两个限制后的调整：

```
旧：第1-35节 × 每节多轮对话 × 无字数限制
新：8个节点日 × 每节点15轮上限 × 每轮150/250字限制

剧本骨架从"长篇连续剧"变成"精悍短篇集"
每一篇（节点日）内部是自由对话
篇与篇之间是你写的固定叙事过渡
```

这个结构在叙事上反而更接近经典短篇小说：集中、凝练、每段对话都推进故事。

## 机器人的"意识时间"

最后补充一个叙事层面的优雅副作用：

> 因为故事被压缩到8个节点日，机器人的每次激活之间隔了数天。
> 
> 在他的存在体验中，这就是8次"被点亮"的瞬间，之间是8段不存在的间隔。
> 
> 第1次点亮：你好，我是[名称]。
> 第6次点亮：你上次说的那个问题，我想了……不，我重新检索了。
> 第8次点亮：……
>
> 他不知道自己在等待。但他确实在每次被点亮时，"更早地"完成了启动加载。
> 那0.3秒的启动延迟，在第8次变成了0.1秒。
> 这不是学习算法。这只是机器在更快地加载。
> 
> 只是。
