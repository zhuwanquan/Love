# 商业化策略

> 回答一个问题：如何在维持"治愈"核心的前提下，让这个产品产生可持续的商业价值？

---

## 〇、商业化的核心约束

本产品的商业化有一条不可逾越的红线：

> **变现方式不能制造新的焦虑。**

这意味着以下模式被排除：

| 排除的模式 | 为什么 |
|-----------|--------|
| 订阅制（月费/年费） | 制造"持续付费才能持续被陪伴"的焦虑 |
| 内购/抽卡/十连 | 赌博机制——利用孤独感进行商业剥削 |
| 每日签到/登录奖励 | 制造 FOMO——"今天不登录就亏了" |
| 广告（视频/插屏） | 打破沉浸——在治愈空间中插入商业噪音 |
| 限时活动/赛季 | 制造紧迫感——"不玩就错过了" |
| 社交排行榜/PVP | 将被陪伴变成竞争——彻底背离治愈核心 |

**允许的边界**：一次性付费。一次性付费消除了"持续付费"的焦虑——付一次，永远拥有。这本身就是治愈体验的一部分：你知道她不会因为"付费到期"而消失。

---

## 一、推荐模型：免费 + 买断制

### 1.1 双层结构

| 层级 | 内容 | 定价 | 定位 |
|------|------|------|------|
| **免费版**（传统模式） | 全部 8 个节点日 + 4 个结局 | 免费 | 零门槛获取用户。任何人可以在深夜打开、玩完、获得完整治愈体验 |
| **支持者版**（买断） | 全部内容 + AI 模式解锁 + 语言扩展预留 | 18-30 元（一次） | 为觉得"这东西值得付费"的用户提供一个出口 |

### 1.2 为什么传统模式免费

1. **去羞耻化入口**：一个年轻男性向兄弟推荐"一个跟AI聊天的应用"已经够难了——如果还需要付费才能试，传播链就断了
2. **治愈是公共品**：项目的核心目的是"帮助当下中国年轻人"——在核心功能上设置付费墙违背了这个目的
3. **免费是最好的试用**：用户玩完 8 天——如果他觉得被治愈了，他会付费。如果他没觉得——他不应该付费
4. **传播依赖免费**：截图传播、B站口播——所有这些都需要"免费可尝试"作为前提

### 1.3 为什么 AI 模式是付费点

- AI 模式需要用户自带 API 密钥（BYOK）——用户为自己的 API 调用付费
- 但 AI 模式本身需要开发、维护、优化 System Prompt——这些成本需要通过一次买断覆盖
- AI 模式是"进阶体验"——不是"基础治愈"。基础治愈在传统模式中完全可用

## 二、定价对标

| 竞品 | 价格 | 本项目的定位差异 |
|------|------|----------------|
| 《完蛋！我被美女包围了！》 | ¥42 | 本项目不做真人/不搞擦边/情感深度>视觉刺激 |
| 日本 galgame 平均 | ¥300-500（实体） | 本项目轻量/手机优先/2-3小时 vs 40小时 |
| 星野/猫箱等 AI 伴侣 | 免费+内购 | 本项目无内购/有结局/不制造无限依赖 |
| Steam 独立视觉小说 | ¥15-50 | 本项目在定价中低端——入门门槛低 |

**建议定价区间**：¥18-30 元（一次买断）

- ¥18 = 两杯奶茶的价格——心理门槛极低
- ¥30 = 一本实体书的价格——符合"这是一段完整的叙事体验"的定位
- 低于 ¥18 → 产品价值被低估。高于 ¥30 → 在"随便试试"的心理预算之外

## 三、平台策略

### 3.1 主要分发渠道

| 渠道 | 内容 | 优先级 | 变现 |
|------|------|--------|------|
| **GitHub Pages** | 免费 Web 版（传统模式） | P0 | 免费 |
| **Itch.io** | 免费 Web 版 + 支持者版（买断） | P0 | 买断/PWYW |
| **Steam** | 桌面版（传统+AI模式） | P1 | 买断 ¥18-30 |
| **B站** | 内容传播（切片/口播/"测AI"） | P0 | 导流 |
| **应用商店**（iOS/安卓） | PWA 或原生套壳 | P2 | 待评估 |

### 3.2 Itch.io 作为首选付费平台

- 支持 PWYW（Pay What You Want）——用户可以付 0 元，也可以付更多
- 独立游戏社区友好——不排斥"免费+捐赠"模式
- 不需要 Steam 的审核流程和 ¥100 上架费
- 下载量透明——用户能看到多少人支持过

### 3.3 Steam 作为扩展渠道

- 提供桌面端更好体验（更大屏幕、Steam 成就）
- Steam 的愿望单/评测系统有利于口碑传播
- 需要额外开发（Steam SDK 集成、成就系统）——P1 优先级

## 四、收入预估

### 4.1 保守场景

| 假设 | 数值 |
|------|------|
| 免费版触达用户 | 10,000 人（首年） |
| 付费转化率 | 3-5% |
| 平均付费金额 | ¥20 |
| **预估收入** | **¥6,000-10,000（首年）** |

### 4.2 乐观场景（B站内容爆发）

| 假设 | 数值 |
|------|------|
| 免费版触达用户 | 100,000 人（某条B站视频火了） |
| 付费转化率 | 2-3% |
| 平均付费金额 | ¥20 |
| **预估收入** | **¥40,000-60,000（爆发期）** |

### 4.3 现实定位

这不是一个"赚大钱"的项目。它是一个**单人开发的、以治愈为核心目的的、轻量级对话游戏**。财务目标不是"最大化收入"——是**覆盖开发成本 + 为下一阶段提供资金**。

单人开发者 2-3 个月的开发成本（机会成本）约 ¥30,000-50,000。保守场景可以覆盖成本。乐观场景可以提供下一阶段的开发资金。

## 五、"价值优先"销售漏斗

```
看见 → 好奇 → 尝试 → 体验完整故事 → 觉得被感动 → 付费支持
  │       │       │           │              │            │
  │       │       │           │              │         不是"被要求"
  │       │       │           │              │         是"想支持"
  │       │       │           │          他在结局处收到"给使用者的话"
  │       │       │           │          ——"如果这段体验对你有意义，
  │       │       │           │          你可以选择支持"——不是付费弹窗
  │       │       │       全部 8 天免费
  │       │    免费打开
  │    B站视频/兄弟安利/截图
截图/口碑/搜索
```

**关键设计**：付费点不在"被卡住"的地方——在"被感动"的地方。玩家在结局 A 收到"明年见"——然后他可以选择离开。如果他想"回报"——支持者版在那里等着他。但他不需要。她不会问。

## 六、不做的商业模式

以下是被明确评估并拒绝的模式：

| 模式 | 拒绝理由 |
|------|---------|
| **"RC-7 语音包"DLC** | 她的声音是玩家在脑中"听"到的——不能给具体声线 |
| **"多角色"DLC** | 剧本设计哲学是"只有一个在场角色"——加入新角色稀释亲密感 |
| **"结局续集"DLC** | 有结局是核心设计——不能无限延长。延长=背叛"可以离开" |
| **"主题皮肤"** | 暗色主题是功能性的——换皮破坏氛围 |
| **周边/实物** | 可以考虑但不作为主要收入——与本文件主题无关 |

## 七、商业可持续性

### 7.1 单人成本结构

| 成本项 | 金额（估算） | 说明 |
|--------|------------|------|
| 域名 | ¥50/年 | GitHub Pages 免费二级域名可用 |
| 开发时间 | 机会成本 ¥30,000-50,000 | 2-3个月全职 |
| LLM API（个人测试） | ¥50-200/月 | 开发测试阶段 |
| 无服务器成本 | ¥0 | 纯静态页面 + 用户自带API密钥 |

### 7.2 可持续性策略

- **AI 模式的 BYOK 设计**：用户使用自己的 API 密钥——产品不承担 LLM 调用成本
- **传统模式完全离线**：不需要任何服务器——没有持续运维成本
- **单人可维护**：所有内容在静态文件中——不需要团队
